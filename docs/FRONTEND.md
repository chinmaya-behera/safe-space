# Login screen setup

The project now supports React, TypeScript, Tailwind CSS and the shadcn component directory structure. No additional initialization is required for the supplied sign-in component.

## File paths

| File or folder | Purpose |
| --- | --- |
| `components/ui/modern-stunning-sign-in.tsx` | Reusable dark sign-in and registration card |
| `components/ui/auth-terms.tsx` | Registration terms and consent checkboxes |
| `components/auth-panel.tsx` | Backend integration, session restoration and sign-out |
| `frontend/main.tsx` | React mount for the login page |
| `frontend/styles.css` | Tailwind imports and login styles |
| `lib/auth-client.ts` | Typed API requests and account data |
| `lib/utils.ts` | shadcn-style class merging utility |
| `components.json` | shadcn aliases and style configuration |
| `vite.config.ts` | Builds the component into `public/auth/` |

`@/components/ui` maps to the repository's `components/ui` directory. This is where future shared UI components should be added so the CLI and component imports stay consistent.

## Install and run

```powershell
npm.cmd install
npm.cmd run build
npm.cmd start
```

Open http://localhost:3000/login. The existing Express server serves the built React assets and API together, so there is no second origin or API proxy to configure.

For ongoing edits, use `npm.cmd run dev`. It watches the React build and backend together. Refresh the page to load a newly built UI. Built assets in `public/auth/` are ignored by Git and generated by the build. Install development dependencies when building on a host, then start the Node server with `node --env-file-if-exists=.env src/server.js` if your deployment starts from already-built assets.

## Add other shadcn components

The project is already manually configured for shadcn. You can add supported components with the CLI, for example:

```powershell
npx.cmd shadcn@latest add button
```

If copying this component into a different, unconfigured project, follow the official [shadcn Vite setup](https://ui.shadcn.com/docs/installation/vite) and [Tailwind Vite installation](https://tailwindcss.com/docs/installation/using-vite). Use the same `@/` aliases and components directory.

## Design adaptation

The pasted reference component provides the dark background, glass card, rounded fields, restrained button and account-switching link. Safe Space keeps its own brand and storage information. Local Lucide icons replace third-party logos and image assets; no remote images or unsupported user-count claims are needed. The form calls the existing account APIs, including all required registration consents.

Google sign-in requires OAuth configuration and backend work before a working Google button can be added. Email verification and password recovery remain outside this update.
